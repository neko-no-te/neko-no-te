# neko-no-te — 事務員の仕事を100個奪う猫｜ネコの手の作り方

ショートアニメ「事務員の仕事を100個奪う猫」に出てくる「ネコの手」（事務の仕事を自動にする道具）の見本です。
お話は架空ですが、道具は実際に動きます。LINE公式アカウントと Google スプレッドシート・Google Apps Script だけで動きます。

| ファイル | ネコの手 | すること |
|---|---|---|
| Code.gs | 1個め「日報すいこみ口」 | LINE で送られた日報と写真が、スプレッドシートの「日報」のシートに1行ずつ入る（現場は列）。写真は Google ドライブの現場ごとのフォルダにしまい、現場ごとの写真台帳（印刷用）に並べる |
| Yugata.gs | 2個め「日報ゆうがた便」 | 毎日17時台に、その日の日報を現場ごとに並べて、1通のメールで送る |
| Mada.gs | 3個め「日報まだ番」 | 毎日18時台（日曜は休み）に、今日の日報が無い現場の担当（その現場に最後に送った人）に LINE で催促し、事務の人に「まだの現場」をメールで知らせる |
| Hogushi.gs | 4個め「日報ほぐし機」 | 届いた日報の文を、AI（Google の Gemini）が「作業の内容・人数・困りごと・明日の予定」に分けて、「日報」のシートの右の列に入れる。困りごとがあればメールで知らせる。中身の無い日報（「いま書くとこ」など）は、3個めが「まだ」と数える |
| Tegaki.gs | 6個め「手書きすいこみ口」 | LINE で「手書き」のボタンを押してから、紙に手で書いた日報の写真を送ると、AI（Gemini）が字を読んで、「日報」のシートに種類「手書き」の1行で入れる。読めなかった字は「？」。4個めが中身を分け、2個め・3個めも日報として数える |
| Shuho.gs | 7個め「週報まとめ係」 | 毎週金曜19時台に、今日までの7日間の日報を現場ごとに集めて、1通のメールで送る。いちばん上に、今週動いた現場と延べ人数（4個めが分けた人数の足し算）。その下に、AI（Gemini）が現場ごとにまとめた「進んだこと・困りごと・来週の予定」と、表へのリンク |

2個め〜7個めは、1個めと同じスクリプトに足して使います（2個めは1個めの関数を、3個めと4個めは1個めと2個めの関数を、6個めは1個め〜4個めの関数を、7個めは1個め・2個め・4個めの関数を使うため、単独では動きません）。5個め「写真ならべ機」は、1個めの写真台帳（Code.gs の中）です。

**大事なこと**

- 見本です。自分の会社で使う前に、自分のアカウントで試して、動きを確かめてください。使ったことで起きたことの責任は負えません（LICENSE のとおり）
- LINE の鍵（チャネルアクセストークン）は、スクリプトの「スクリプト プロパティ」にだけ入れます。コードやスプレッドシートに貼らない・人に見せない・画面を録画しない
- 送った人の名前と LINE の番号は、表に残しません（番号は、元に戻せない形に変換して使います）。3個めを入れたときだけ、催促の宛先として、現場ごとに最後に送った人の LINE の番号を、スクリプト プロパティ（表を共有した人には見えない所）に持ちます
- スプレッドシートを共有する相手は、必要な人だけにしてください（日報と写真が入ります）
- 4個めは、日報の文を外の AI（Google の Gemini）に渡します。日報を外の AI に渡してよいかを、会社で決めてから使ってください（下の「4個め」の注意も読む）
- 6個めは、手書きの日報の写真を外の AI（Google の Gemini）に渡します。写真に人の名前などが写るときは、外の AI に渡してよいかを、会社で決めてから使ってください（下の「6個め」の注意も読む）
- 7個めは、1週間ぶんの日報の文を外の AI（Google の Gemini）に渡します。4個めと同じく、外の AI に渡してよいかを、会社で決めてから使ってください

## 1個め「日報すいこみ口」を入れる（約30分）

LINE や Google の画面は変わることがあります。項目の名前がこの手順と違うときは、近い名前のものを探してください。

### 1. LINE公式アカウントを作る

1. LINEヤフー for Business の「LINE公式アカウント」のページから、無料のアカウントを作る
2. 認証済みアカウントの申請はしなくても動きます

### 2. プログラムから使う入口を開け、LINE の鍵を出す

1. LINE Official Account Manager の右上「設定」→ 左の「Messaging API」→「Messaging APIを利用する」（プロバイダーは新しく作るか、今あるものを選ぶ）
2. LINE Developers のコンソールを開き、そのチャネル →「Messaging API設定」のいちばん下の「チャネルアクセストークン（長期）」で「発行」を押す
3. 出てきた長い文字列（LINE の鍵）をコピーしておく。**人に見せない**

### 3. スクリプトを作って、鍵を入れる

1. https://script.google.com で「新しいプロジェクト」を作る（スプレッドシートとは別のファイルにする。誰とも共有しない）
2. 最初からある中身を消して、Code.gs の中身をまるごと貼り、保存する
3. 左の歯車「プロジェクトの設定」→ いちばん下の「スクリプト プロパティ」→「スクリプト プロパティを追加」。プロパティに `LINE_TOKEN`、値に 2 でコピーした鍵を貼り、保存する

### 4. 準備のプログラムを1回動かす

1. エディタの上で、動かす関数に `setup` を選んで「実行」
2. 初めてのときは「承認が必要です」が出る →「権限を確認」→ 自分のアカウント →「詳細」→「（安全ではないページ）に移動」→「許可」（自分で作ったスクリプトなので、この注意が出ます）。許可する項目ごとに印の箱が出たときは、全部に印を付けてから進む（1つでも外すと、プログラムが途中で止まります）
3. 下の「実行ログ」に、表とフォルダの住所、参加の合言葉の行、`?k=` で始まる行が出る。**この2行は手で打たずにコピーする**（1 と l、0 と O を打ち間違えやすい）。**この画面は人に見せない**

setup がやること: スプレッドシートと写真のフォルダを作る／「日報」「現場」「受付の記録」のシートと、現場1〜4のフォルダを用意する（「現場」のシートの工事名は自分で入れる）／受け取り先の合言葉・参加の合言葉・番号を変換する鍵を作って、スクリプト プロパティにしまう。写真と受付の記録は、何か届いたときに置かれる「1分後に1回だけ動く自動実行」でしまいます（毎分は動かさないので、何も届かない日は自動実行の時間を使いません）。何回動かしても、シートやフォルダは増えません。

### 5. ウェブアプリとして公開する

1. 右上「デプロイ」→「新しいデプロイ」→ 種類の歯車で「ウェブアプリ」
2. 「次のユーザーとして実行」は「自分」、「アクセスできるユーザー」は「全員」（LINE がログインなしで届けるため。合言葉で守ります）
3. 「デプロイ」→ 出てきた「ウェブアプリの URL」をコピー

### 6. LINE の画面で、受け取り先をつなぐ

1. LINE Developers の「Messaging API設定」→「Webhook URL」の「編集」。5 の URL の後ろに、4 の実行ログに出た `?k=…` を付けて貼り、「更新」
2. 「Webhookの利用」をオンにする。**「検証」は、合言葉が違っていても「成功」と出ます**（プログラムが中身を返さないため）。つながったかは、7 でスマホから参加の合言葉を送り、返事が来るかで確かめる
3. 応答設定で「応答メッセージ」と「あいさつメッセージ」をオフ、「Webhook」をオンにする（あいさつはプログラムが送る）
4. 「グループトーク・複数人トークへの参加を許可する」と「Webhookの再送」は、切ったままにする

### 7. スマホで試す

1. 自分のスマホから、そのアカウントを友だちに追加する
2. 参加の合言葉を1回送る →「参加を受け付けました」とボタンが出る
3. 「現場1」を押す → 日報を一言送る → 写真を2〜3枚送る
4. 表の「日報」のシートと、ドライブの「現場1」のフォルダに入ったかを見る（写真は2分ほどで入ります）
5. 写真を送ったあと5分以内に一言を送ると、写真台帳（「台帳_現場1」）の枠に、その一言が入る

**守り**: 受け取り先の住所の合言葉・宛先・参加の合言葉の3つで、関係ない知らせを落とします。1日100件・1人30件まで／文と写真だけ／「=」などで始まる文は計算式として動かないよう文のまま入れる／返事は Reply だけ（無料の通数を使わない）。

## 2個め「日報ゆうがた便」を足す（約5分）

1. スクリプトの左「ファイル」の「＋」→「スクリプト」→ 名前を `Yugata` にして、Yugata.gs の中身をまるごと貼り、保存する
2. 動かす関数に `setupYugata` を選んで「実行」（メールを送る許可が新しく要るので、許可の画面が出ます。1個めの 4 と同じように進み、項目ごとの印は全部付ける）
3. 表の「設定」のシートの「ゆうがた便の送り先」の右のマスに、送り先のメールアドレスを入れる（カンマか読点で区切れば何人にでも）
4. 試すときは、動かす関数に `sendYugata` を選んで「実行」→「今日の日報（11/21）」のようなメールが届く
5. あとは毎日17時台に、ひとりでに届きます。止めるときは、左の目覚まし時計「トリガー」で sendYugata の自動実行を消す

メールに入るのは、動いた時点までに届いた今日の日報だけです（写真の行は入れない）。日報が1件も無い日も、日曜も、休まずに送ります。送り先が空・メールアドレスでないものがある・メールの送信の上限（無料のアカウントは1日100人ぶん）の残りが足りない日は、送らずに止まります。

## 3個め「日報まだ番」を足す（約5分）

2個め（Yugata.gs）が入っていることが前提です（自動実行を消していても、ファイルが入っていれば動きます）。

1. 「ファイル」の「＋」→「スクリプト」→ 名前を `Mada` にして、Mada.gs の中身をまるごと貼り、保存する
2. 動かす関数に `setupMada` を選んで「実行」→「現場」のシートに「今日は動く」の列（チェックの箱・はじめは全部に印）、「設定」のシートに「まだ番の知らせ先」の欄、毎日18時台の自動実行ができる
3. 「まだ番の知らせ先」の右のマスに、事務の人のメールアドレスを入れる。休みの現場は「今日は動く」の印を外す
4. 担当は、このあと各現場に日報か写真を送った人から覚えます（前に届いた分からは覚えない）。一度も届いていない現場は、知らせのメールに「担当がまだ分かりません」と出ます
5. 試すときは、動かす関数に `sendMada` を選んで「実行」

- 数えるのは文の日報だけです（写真だけの現場には催促します）。日曜は送りません
- 催促は LINE のお知らせ（Push）なので、無料のプランでは月200通（宛先の人数で数える）の中で送ります。断られた現場（無料の通数を使い切ったときなど）は、知らせのメールに「催促を送れませんでした。電話でお願いします」と出ます
- 催促を受け取った人は、30分のあいだ、現場を選ばずにそのまま日報を返せます
- 止めるときは「今日は動く」の印を全部外すか、「トリガー」で sendMada の自動実行を消す

## 4個め「日報ほぐし機」を足す（約15分）

2個め（Yugata.gs）が入っていることが前提です。AI を呼ぶ道具なので、使った分だけ料金がかかります（下の「料金とデータの扱い」）。

1. https://aistudio.google.com を開き、左の「Get API key」（API キー）→「API キーを作成」。出てきた長い文字列（AI の鍵）をコピーしておく。**人に見せない**
2. スクリプトの「プロジェクトの設定」→「スクリプト プロパティ」→「スクリプト プロパティを追加」。プロパティに `GEMINI_API_KEY`、値に 1 の鍵を貼り、保存する
3. 「ファイル」の「＋」→「スクリプト」→ 名前を `Hogushi` にして、Hogushi.gs の中身をまるごと貼り、保存する
4. 動かす関数に `setupHogushi` を選んで「実行」→ 架空の日報1件で AI を呼べるかを確かめてから、「日報」のシートの右に5つの列（作業の内容・人数・困りごと・明日の予定・ほぐし）と、「設定」のシートに「ほぐし機の知らせ先」の欄ができる。新しい許可は、ふつうは求められません（1個めが LINE を呼ぶ許可を使います）。許可の画面が出たときは、1個めの 4 と同じように進む
5. 「ほぐし機の知らせ先」の右のマスに、困りごとを知らせる人のメールアドレスを入れる（カンマか読点で区切れば何人にでも）
6. 「デプロイ」→「デプロイを管理」→ 鉛筆の印 →「バージョン」で「新バージョン」→「デプロイ」（日報が届いたあとに動く片付けは、公開した版のプログラムで動くため。公開し直さないと、Hogushi.gs の無い前の版で動き、日報を読みません。住所は変わりません）。Hogushi.gs をあとで直したときも、同じように公開し直す
7. スマホから日報を1つ送る → 2分ほどで、その行の右の列に入る

- 読むのは、4 のあとに届いた日報だけです。前からある日報には「入れる前」の印が付き、読みません
- AI は読みちがえることがあります。元の文は書き換えずに横に残るので、人数や困りごとは元の文で確かめてください
- 「ほぐし」の列: 済（読んだ）／知らせ待ち（困りごとを、まだ知らせていない。知らせ先が空・メールの上限のときは、次の回に知らせる）／中身なし（作業の内容が無い日報。3個めは、その現場を「まだ」と数える）／もう一度1・2（AI の返事に無かったので、次にもう一度読む）／読めず（3回読めなかった。人が見る）
- AI の窓口が混んでいる・料金の残高が無い・通信が切れたときは、10分あけて読み直します。鍵が違うときは止まり、Google から持ち主にメールが届きます
- AI には、日報の文と通し番号だけを渡します（現場の名前・受付番号・送った人は渡しません）
- 1回に読むのは20件までです（残りは次の回）

### 料金とデータの扱い（2026年11月に、Google の公式のページで確かめた内容。変わることがあります）

- **無料の枠のまま使うと、送った日報が Google の製品の改善に使われ、人が読むこともあります**（Gemini API の利用規約。個人の情報を送らないように、と書かれています）。名前や現場名が入る本物の日報を流す前に、有料の枠に切り替えてください。試すときは、架空の日報だけにする
- 有料の枠にするには、AI Studio の「API キー」か「プロジェクト」の画面で「Set up billing」から請求先をつなぎ、前払いをします（最低5ドル。12か月で失効し、返金されません）。有料の枠では、送った文は Google の改善に使われません。Google Workspace のアカウントでも、請求先をつながないと無料の枠の扱いです
- **有料の枠にしたら、AI Studio の「ログ」の画面で、送った内容の保存（最長55日）をオフにする**（2026年10月26日より後に作ったプロジェクトは、はじめから保存がオンです）
- 料金のめやす: 型は gemini-3.5-flash-lite（入力100万トークンあたり0.30ドル・出力2.50ドル）。1日50件・1件の日報が短い文なら、月に1ドルほど（実際の支払いは、前払いの最低額で決まります）
- AI の鍵は、スクリプト プロパティにだけ入れます。スクリプトは誰とも共有しないでください（共有すると、相手が鍵を読めます）

## 6個め「手書きすいこみ口」を足す（約10分）

4個め（Hogushi.gs）が入っていることが前提です（同じ AI の鍵を使い、読んだ文を4個めが分けます）。AI を呼ぶ道具なので、使った分だけ料金がかかります（4個めの「料金とデータの扱い」と、下の料金のめやす）。

1. スクリプトの Code.gs・Yugata.gs・Mada.gs・Hogushi.gs の中身を、新しい版にまるごと置き換えて保存する（「手書き」のボタンと、手書きを日報として数える所が入っています）
2. 「ファイル」の「＋」→「スクリプト」→ 名前を `Tegaki` にして、Tegaki.gs の中身をまるごと貼り、保存する
3. 動かす関数に `setupTegaki` を選んで「実行」→ AI を呼べるかを確かめて、「準備ができました」と記録に出る。新しい許可は、ふつうは求められません（1個めがドライブと外を呼ぶ許可を使います）
4. 「デプロイ」→「デプロイを管理」→ 鉛筆の印 →「バージョン」で「新バージョン」→「デプロイ」（Code.gs を置き換えたので、受け取り口も新しい版にする。住所は変わりません）
5. スマホで現場を選ぶ → 返事の「手書き」を押す → 紙の日報の写真を送る →「受け付けました（現場1・手書き1枚）」と返事が来る → 2分ほどで、「日報」のシートに種類「手書き」の行が入る

- 「手書き」を押してから10分のあいだに送った写真が、手書きの日報になります（現場を選び直すと、押し直し）。ふつうの工事写真は、押さずに送る
- 読めなかった字は「？」になります。AI は読みちがえることがあるので、**数字（人数・時刻・数量）は、行の写真のリンクを開いて見比べてください**
- 内容が「（読み取り待ち）」の行は、AI がまだ読んでいない行です（AI の窓口が混んでいるときは、10分あけて読み直します）。「（読めませんでした。写真を見てください）」「（日報の字が見つかりませんでした。写真を見てください）」の行は、人が写真を見て内容を書き直してください（書き直した文は、次に日報が届いたときに4個めが分けます）
- 手書きの日報の写真は、写真台帳には貼りません（工事写真ではないため）。写真は現場のフォルダにしまいます
- 手書きの日報も、2個め（夕方のメール）に並び、3個め（まだ番）は届いたと数えます
- AI には、写真と「文字に起こして」という頼みだけを渡します（現場の名前・受付番号・送った人は渡しません）
- 1回に読むのは5枚までです（残りは次の回）。読む前の手書きの写真が60枚たまっているとき（AI の窓口が長く止まっているなど）は、「混んでいます」と返事して受け付けません。10MBを超える写真は読めません
- 料金のめやす: スマホの写真1枚は、AI の数え方で1,000〜1,600トークンほど（Google の公式のページの説明から数えためやす）。gemini-3.5-flash-lite の有料の枠なら、1枚0.1〜0.2円ほどです。**無料の枠のまま使うと、送った写真が Google の製品の改善に使われ、人が見ることもあります**。名前の入る本物の日報を流す前に、有料の枠に切り替えてください（4個めの「料金とデータの扱い」）

## 7個め「週報まとめ係」を足す（約5分）

4個め（Hogushi.gs）が入っていることが前提です（4個めが分けた「人数」の列を足し算し、同じ AI の鍵を使います）。AI を呼ぶ道具なので、使った分だけ料金がかかります（4個めの「料金とデータの扱い」と、下の料金のめやす）。

1. スクリプトの Yugata.gs の中身を、新しい版にまるごと置き換えて保存する（何日かぶんの日報を拾う所が入っています。2個め・3個めの動きは変わりません）
2. 「ファイル」の「＋」→「スクリプト」→ 名前を `Shuho` にして、Shuho.gs の中身をまるごと貼り、保存する
3. 動かす関数に `setupShuho` を選んで「実行」→ AI を呼べるかを確かめてから、「設定」のシートに「週報の送り先」の欄と、毎週金曜19時台の自動実行ができる。新しい許可は、ふつうは求められません（2個めのメールの許可と、4個めが外を呼ぶ許可を使います）
4. 「週報の送り先」の右のマスに、社長など、まとめを受け取る人のメールアドレスを入れる（カンマか読点で区切れば何人にでも）
5. 試すときは、動かす関数に `sendShuho` を選んで「実行」→「今週のまとめ（11/21〜11/27）」のようなメールが届く。左の目覚まし時計「トリガー」に sendShuho が並び、鉛筆の印を開くと「週ベースのタイマー」「毎週金曜日」「午後7時〜8時」になっているかも見る（見るだけなら「キャンセル」で閉じる）

- 「今週」は、動いた日までの7日間です（金曜に動けば、土曜〜金曜。手で動かした日も同じ数え方）
- 延べ人数は、4個めが分けた「人数」の列の足し算です（AI には数えさせません）。人数の分からない日報（書いていない・4個めがまだ読んでいない・手書きが読めなかった）は足さずに、件数を添えます。人数を表で直すと、次のまとめから直した数で足します。同じ日に同じ現場から2回送られた日報は、2回とも足します
- 4個めが「中身なし」の印を付けた日報は数えません。写真の行も数えません
- AI のまとめは、まちがえることも、大事なことを落とすこともあります。メールの下のリンクから、元の日報で確かめてください。元請けなど外に出す文に、そのまま使わないでください
- AI の窓口が混んでいる・料金の残高が無い・通信が切れたときは、1分あけて3回まで読み直し、それでもだめなら人数だけのメールを送ります。鍵が違う・無いときは、人数だけのメールを送ってから止まり、Google から持ち主にメールが届きます
- 送り先が空・メールアドレスでないものがある・メールの送信の上限（無料のアカウントは1日100人ぶん）の残りが足りない日は、AI も呼ばずに止まります
- AI には、日報の文と日付と通し番号だけを渡します（現場の名前・受付番号・送った人は渡しません）
- 料金のめやす: 週に1回、AI を1回呼びます。4現場で1週間ぶんの日報が長い文でも、gemini-3.5-flash-lite の有料の枠なら1回1円に届きません（4個めの料金から数えためやす）

## 使うのをやめるとき

LINE Developers で「Webhookの利用」をオフ → スクリプトの「デプロイ」→「デプロイを管理」で、ウェブアプリをアーカイブ → 「トリガー」で自動実行（drainPhotos・sendYugata・sendMada・sendShuho）を消す → 「スクリプト プロパティ」で `LINE_TOKEN` と、3個めを入れていたら `SENDERS` を、4個めを入れていたら `GEMINI_API_KEY` を消す（AI Studio でも、その鍵を消す）。
